# SVG 2, Chapter 2: Conformance Criteria

## Error processing: path-grammar, gradient-radial-geometry

- [x] svg2/conform.md#ErrorProcessing: a document fragment is in error when non-conforming for its document type, or elsewhere stated as in error (e.g. an invalid attribute value)
- [x] svg2/conform.md#ErrorProcessing: when in error, rendering continues for the rest of the document; only the element, or the part of it that is in error, is not rendered

## CTM and coordinate precision: transform-double (exists)

- [x] svg2/conform.md#ConformingSVGViewers: intermediate numerical calculations for converting coordinates must use at least single-precision floating point
- [x] svg2/conform.md#ctm-matrix: to avoid rounding error on coordinate transformation, the CTM is generated by multiplying two double-precision parent/local matrices and only then rounding the product to single precision
- [x] svg2/conform.md#ctm-matrix2: viewport coordinates are obtained as the single-precision CTM applied to the single-precision user-space coordinates
- [x] svg2/conform.md#ctm-matrix2: for nested viewports, the ScreenCTM (the nested CTM transforming user coordinates to device coordinates) must likewise be generated using double-precision floating point
- [-] svg2/conform.md#ConformingHighQualitySVGViewers: a high-quality viewer must use at least double-precision floating point for coordinate-system transformation calculations generally, not only for CTM generation (D18)

## Conforming viewer rendering requirements: paint-rendering-hints, render-groups

- [x] svg2/conform.md#ConformingSVGViewers: the viewer must support at least Simple Alpha Compositing when compositing an image of SVG content with opacity below 100% onto the target canvas
- [x] svg2/conform.md#ConformingSVGViewers: resampling of image data must be consistent with the image-rendering property
- [x] svg2/conform.md#ConformingSVGViewers: all visual rendering must be accurate to within one device pixel of the mathematically correct result at the initial 1:1 zoom ratio
- [x] svg2/conform.md#ConformingSVGViewers: on systems with accurate sRGB support, sRGB color computations and resulting values must be accurate to within one sRGB component value (range 0-255)

## High-quality viewer requirements: paint-rendering-hints

- [x] svg2/conform.md#ConformingHighQualitySVGViewers: on low-resolution devices (150dpi or less) a high-quality viewer must support smooth (anti-aliased) edges on lines and curves
- [-] svg2/conform.md#ConformingHighQualitySVGViewers: a high-quality viewer must support color management via ICC profiles (D18)
- [x] svg2/conform.md#ConformingHighQualitySVGViewers: a high-quality viewer's image resampling must meet the stricter image-rendering requirements given for high-quality viewers
