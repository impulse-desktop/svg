## CTM and coordinate precision: transform-double (exists)

- [x] svg2/conform.md#ConformingSVGViewers: intermediate numerical calculations for converting coordinates must use at least single-precision floating point [transform-double#viewbox-offset]
- [x] svg2/conform.md#ctm-matrix: to avoid rounding error on coordinate transformation, the CTM is generated by multiplying two double-precision parent/local matrices and only then rounding the product to single precision [transform-double#viewbox-offset transform-double#css-transform]
- [x] svg2/conform.md#ctm-matrix2: viewport coordinates are obtained as the single-precision CTM applied to the single-precision user-space coordinates [transform-double#viewbox-offset]
- [x] svg2/conform.md#ctm-matrix2: for nested viewports, the ScreenCTM (the nested CTM transforming user coordinates to device coordinates) must likewise be generated using double-precision floating point [transform-double#nested-viewport]
- [-] svg2/conform.md#ConformingHighQualitySVGViewers: a high-quality viewer must use at least double-precision floating point for coordinate-system transformation calculations generally, not only for CTM generation (D18) [transform-double#css-transform]
